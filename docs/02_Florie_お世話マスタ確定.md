## 2. 採用する構成

初期版は、水道水のみで飾る場合を標準にする。

| 項目 | 確定仕様 |
|---|---|
| 水を替える | 全8種類、1日周期 |
| 茎を確認して整える | 全8種類、3日周期 |
| care_templatesの件数 | 8種類×2件＝16件 |
| 花ごとの差 | 説明文、水量、切り方、注意事項に反映 |
| 水量・置き場所 | 定期タスクにせず、いつでも読める説明として扱う |
| 登録当日の準備 | 登録時に案内し、定期タスクにしない |
| 季節・室温・延命剤による周期変更 | 初期版では自動化しない |

1日・3日は、すべての花に共通する唯一の最適周期ではない。調査した推奨範囲から、初心者が扱いやすい固定周期として選んだFlorieの設計判断である。花種ごとに周期を変える十分な根拠がないため、無理に差を設けない。

## 3. 調査結果と採用理由

### 3.1 水替えは1日周期

農林水産省は毎日、日比谷花壇は毎日または1～2日に1回、青山フラワーマーケットは水道水のみの場合に毎日の水替えを案内している。水道水を標準とするFlorieでは1日周期を採用する。[S1][S2][S3][S4]

チューリップの産地資料には2～3日に1回でよいという案内もある。ただし室温や水の状態への言及があり、全家庭で一律に3日空けられる根拠とは扱わない。[S6]

### 3.2 茎の手入れは3日周期

| 情報源 | 案内 | 採用時の解釈 |
|---|---|---|
| 日比谷花壇・基本のお手入れ | 活けた後も2～3日に一度、水切り | 3日周期の共通根拠 |
| 青山フラワーマーケット・基本の手入れ | 水替えのたびに切り戻す | より頻繁な手入れをすすめる資料もある |
| 青山フラワーマーケット・カーネーション | 茎先が茶色くなったら切る | 状態に応じた対応を含める |
| にいがた ちゅーりっぷ図鑑 | 水替え時、茎が茶色く傷んでいれば切る | 毎日の切断を一律に義務化しない |

出典：[S2][S4][S5][S6]

毎日2件を完了する構成は採用せず、水替え時に軽く茎を確認し、独立した茎の手入れを3日周期にする。水替え時の確認に別のチェックボックスは設けない。

傷みがあれば予定を待たずに対応する。直前に切ったばかりなら、茎のタスクは確認だけで完了できる。「3日間は必ず切らなくてよい」「全種類で毎日切ると有害」とは断定しない。

ダリアには毎日の切り戻しをすすめる花別資料もある。その推奨を否定せず、毎日の水替え時にも傷みを確認する説明と組み合わせ、独立した予定は3日周期にまとめる。[S7]

## 6. 登録当日の準備と共通案内

### 6.1 登録時の案内

初回予定日は登録日＋周期のため、登録当日の準備を定期タスクとは別に案内する。

> はじめに、花瓶を洗い、水につかる葉を取り除きましょう。茎先を少し切って、花に合った量の水に挿してください。すでに準備が済んでいる場合は、やり直さなくて大丈夫です。

清潔な花瓶、水中の葉の除去、切り口を整えることは専門店の基本案内に基づく。[S4]

### 6.2 いつでも読める共通案内

- 直射日光と冷暖房の風が直接当たる場所を避け、涼しい場所に飾る。
- 予定を待たず、水が濁ったり、ぬめりが出たりしたら水替え・洗浄を行う。
- 水が減って切り口が出そうなら、次の予定まで放置しない。
- 茎が短くなったら、切り口が水につく小さな花瓶に替える。

置き場所と、短くなった茎に合う器への変更は日比谷花壇の案内による。[S3] 予定日前にも対応することは、状態を優先するFlorieの運用ルールである。

水量・注意事項には完了ボタンを付けず、予定・履歴を作らない。新しい専用画面は増やさず、登録画面とホームの短い説明欄で扱い、既存のUIに合わせて配置する。

## 7. 切り花用延命剤に関する注意

延命剤には毎日の全交換が不要になる製品がある。青山フラワーマーケットの案内でも、水道水のみと鮮度保持剤の希釈液では交換目安が異なる。延命剤使用中も必ず毎日全交換するとは表示しない。[S4][S16]

共通注記として次を表示する。

> この予定は、水道水だけで飾る場合の目安です。切り花用延命剤を使う場合は、製品に書かれた薄め方と水替え方法を優先してください。

- 初期版では使用製品の登録や周期の切り替えを作らない。延命剤利用者に最適化された予定にはならないという制約が残る。
- 水替え不要の日は、水量・水の状態を確認し、製品の案内に沿った手入れを済ませた時点で完了できる。
- 履歴は「案内に沿ったお世話の完了」であり、必ず全量交換したことを証明する記録とは扱わない。
- 延命剤投入を別の定期タスクにしない。
- 砂糖・漂白剤・洗剤などの自家配合は、初期のお世話案内に入れない。

## 8. 予定日と完了の扱い

既存の日付計算を変更しない。登録日は花をアプリに登録した日とし、購入日を推測して遡らせない。

| お世話 | 初回予定日 | 完了後の次回予定日 |
|---|---|---|
| 水を替える | 登録日＋1日 | 実際の完了日＋1日 |
| 茎を確認して整える | 登録日＋3日 | 実際の完了日＋3日 |

- 9月14日に登録した場合、水替えの初回は9月15日、茎の手入れの初回は9月17日。
- 9月17日予定の茎の手入れを9月18日に完了したら、次回は9月21日。
- 登録当日の定期タスクは表示しない。準備は第6章の案内で扱う。
- 今日以前の予定を表示し、期限を過ぎても未完了予定を表示し続ける。未完了の日数分のタスクを増やさない。
- 水替え時に先に茎を切っても、別タスクの予定日を自動変更しない。
- 茎のタスクが表示された日に確認し、直前に切っていて追加の切断が不要なら、確認だけで完了する。前倒し完了やタスク間の連動機能は追加しない。
- 水替えと茎の手入れが同じ予定日なら、実際の作業は一緒に行ってよい。画面上では各タスクをそれぞれ完了する。
- 各完了時に履歴を保存し、そのタスクの次回予定日を更新する。元の予定日を基準にしない。

## 9. 実装への引き継ぎ事項

### 9.1 説明文の保存先に関する案

以下を実装への引き継ぎ案として記録する。

| 保存先 | 保持する必要がある情報 | 用途 |
|---|---|---|
| care_templates | ユーザー向けのお世話説明文 | 第4章の各タスクの説明。名前と周期だけでは伝わらない切り方・確認内容を表示する |
| flower_types | 花ごとの水量・注意事項 | 第5章の花別案内。周期タスクから分け、登録時・ホームで参照する |

既存の確定資料では説明保存用カラムは未採用である。本資料は上記の保存先案を追加するが、具体的なカラム名・型・文字数・必須制約は、実装時に既存設計と整合させて明示する。既に存在するカラムとして扱わない。

花登録時にcare_tasksへ説明文もコピーするか、マスタを参照して表示するかは、既存の名前・周期のコピー方式と合わせて実装時に明示する。今回この方式を固定したり、コード変更したりしない。

### 9.2 実装上の要件と範囲

- care_templatesの初期値は第4章の16件とする。各花に水替え1件・茎の手入れ1件が対応することを確認する。
- 花の種類は確定した8種類・確定順のままとする。
- 説明文を省略すると「必要に応じて切る」「延命剤は製品説明を優先する」という条件が伝わらないため、名前と周期だけで画面を完成させない。
- 第4章の茎の共通補足、第6章の共通案内、第7章の延命剤注記も表示対象とする。共通文を花ごとに重複保存する必要はない。
- 水量などを周期0日のタスクやダミーの完了履歴で表現しない。
- 根拠・出典は本資料に保持する。出典管理のためだけの新しいDBテーブルは不要。
- 湯揚げ、焼き揚げ、花ごとの薬剤調整などは初期の定期タスクに含めない。
- UIの「茎を少し切る」は本資料の「茎を確認して整える」と整合させる。Figmaの配色・配置・雰囲気を保つ。
